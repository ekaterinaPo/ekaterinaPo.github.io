Land Cover Segmentation

Can a model label every pixel of a satellite image as forest, water, farmland or city, and can it run in production with automated deployment, not just in a notebook?

This project covers the full path from model to production: a U-Net for 7-class segmentation, Docker images in Amazon ECR, three AWS Lambda serving paths, and a GitHub Actions CI/CD pipeline that deploys every code change.

Architecture

The model is trained once and its weights are stored in S3. Code changes go through GitHub Actions to Amazon ECR and on to three Lambda functions, which load the model to answer requests from three kinds of users.

Who can use it, and how

Web app (main demo)

A user uploads a satellite image in a Streamlit app. API Gateway sends it to Lambda, and the app shows the original and the colored land-cover map side by side, with a download button.

Developer API

A FastAPI app on Lambda, reached through a Lambda Function URL. Other systems send an image and get the prediction back as data.

Automated batch

Dropping an image into an S3 bucket triggers Lambda, which writes the predicted map back to S3. No user interaction needed.

What I did

  1. Trained a U-Net in PyTorch on the DeepGlobe Land Cover dataset (satellite images labeled pixel by pixel, resized to 512×512). U-Net keeps fine spatial detail through its skip connections, which matters when every pixel needs a label.
  2. Stored the model in S3. The training script uploads the weights directly, so every Lambda loads the same model.
  3. Packaged inference in Docker images stored in Amazon ECR (Elastic Container Registry), which is how Lambda runs a PyTorch model that is too large for a standard package.
  4. Built CI/CD with GitHub Actions. One workflow per Lambda: on every push to GitHub it builds the Docker image, pushes it to Amazon ECR and updates the Lambda function to the new image, so a code change reaches production without manual steps.
  5. Deployed three Lambda functions with different triggers (S3 event, API Gateway, Function URL) for three kinds of users, and built the Streamlit app as the user-facing demo.
