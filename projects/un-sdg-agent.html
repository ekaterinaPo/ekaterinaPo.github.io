UN Sustainable Development Goals (SDG) SQL Agent

Can a policy analyst ask a question in plain English, like "Which Sub-Saharan African countries improved most in health since 2015?", and get a correct, checked answer from a large database without writing SQL?

The Sustainable Development Goals (SDGs) are 17 goals adopted by all UN member states in 2015, covering poverty, health, education, inequality, climate and more. Each goal is tracked with indicators for every country.

I worked inside the UN system at UNDP before moving into data, so this project is personal: it makes UN development data easier to question.

How it works

The agent works like an analyst: it looks at the database, writes a query, checks the result and tries again if something is wrong.

A real example from the logs

Which Sub-Saharan African countries improved most in SDG 3 (health) since 2015?
The database has individual indicators, not a ready health score, so I built one: all 17 SDG 3 indicators (maternal and child mortality, TB, HIV, life expectancy, health coverage and others), each scaled 0-100, then averaged.

The database

I built the database from the Sustainable Development Report and World Bank files. Five tables, linked by country and indicator codes.

countries193 rows
  • country_code PK
  • country_name
  • region, income_group
  • population, gdp_per_capita
sdg_goals17 rows
  • goal_id PK
  • goal_name
  • goal_short
sdg_indicators123 rows
  • indicator_code PK
  • goal_id → sdg_goals
  • indicator_name, unit
  • target_value, target_direction
sdg_values293,248 rows
  • country_code → countries
  • indicator_code → sdg_indicators
  • year, value, source
sdg_index_scores5,187 rows
  • country_code → countries
  • year
  • sdg_index_score, sdg_rank

What I did

  1. Built the database. Cleaned and joined the SDG indicator panel, the codebook and World Bank income and GDP data into a 5-table SQLite database.
  2. Built the agent with LangGraph. The older LangChain SQL agent did not work with current Claude models, so I moved to LangGraph's native tool calling.
  3. Profiled cost and cut it. The first version cost $0.39 per question. The logs showed that the number of agent turns, not the size of the schema, drove cost. A local entity resolver and a cached schema removed the wasted turns: $0.06-0.13 per question.
  4. Logged everything. Every question, every SQL attempt, the result, the answer and the exact token cost go to an audit log, so the numbers above are measured, not estimated.
